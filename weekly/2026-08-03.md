## 本周重点解读

### 1. MCP 已从“工具协议”进入“应用运行时协议”阶段

2026-07-28 版本最重要的变化不是新增几个字段，而是协议定位发生变化：无状态核心更适合普通 HTTP 基础设施；Tasks 承接长任务；MCP Apps 承接服务端渲染 UI；Extensions 允许能力独立演进。对于已有 ToolHub 或 MCP Server，建议建立一套兼容性检查：

- 是否依赖握手后保存的隐式会话状态；
- 是否能在无 sticky session 的情况下水平扩展；
- 工具 Schema 是否兼容 JSON Schema 2020-12；
- 长任务是否可迁移到 Tasks；
- OAuth、OIDC、Token audience 和权限边界是否清晰；
- Roots、Sampling、Logging 等旧能力是否有替代路径。

### 2. Agent Memory 的关键问题从“能否召回”变成“记忆是否仍然真实”

长期 Agent 的失败常常不是 Recall 不够，而是记忆过期、冲突、重复或时间范围错误。评测应从静态 QA 扩展到持续写入场景，至少覆盖：

- 用户偏好发生变化后的新旧事实冲突；
- `valid_from` / `valid_until` 与 as-of 查询；
- 删除再写入后的重复记忆；
- 时区与日期边界；
- 不确定时能否正确拒答，而不是从过期记忆中自信作答。

### 3. 多 Agent 系统选模型时，后训练差异可能比模型家族更重要

传统做法常用“不同模型家族”获得多样性，但最新研究提示，同一基座经过不同 reasoning distillation、instruction tuning 或 preference/RL 配方后，也会形成不同的质疑、修复、迎合和保守行为。因此，多 Agent Panel 应通过交互行为指标来选成员，而不是仅按厂商或模型家族去重。

### 4. Benchmark 需要从排行榜转向能力剖面

Open SLM Leaderboard 的 specialist model 案例说明，单项极高分可以抬高平均排名，却不代表通用能力。建议模型评估至少同时展示：

- 分任务成绩与方差；
- 是否针对测试集或相似合成数据训练；
- 通用任务与专门任务的能力差距；
- 多次运行稳定性；
- 与实际业务任务成功率之间的相关性。

## 建议优先实践的三个实验

1. **MCP Tool Retrieval 实验**：在 10、20、50、100 个工具规模下，对比全量 Schema、Embedding 路由、LLM Router 和分层路由的工具选择准确率、Token 成本与延迟。
2. **Agent Memory 时间一致性评测**：构造用户偏好更新、撤回、冲突、过期和跨时区样本，对比普通向量记忆与带版本/有效期的结构化记忆。
3. **多 Agent 行为多样性实验**：固定基座模型，对比 SFT、Reasoning Distill、DPO/GRPO 后模型在质疑率、修复率、迎合率、结论一致性和最终正确率上的差异。

## 本周趋势判断

- **MCP 正从连接标准扩展为 Agent 应用层运行时。**
- **Agent Memory 的核心竞争力是时间一致性和可维护性，而不仅是召回率。**
- **后训练配方正在成为多 Agent 系统设计中的独立模型维度。**
- **评测体系必须防止专门模型通过单项基准获得虚高综合排名。**
