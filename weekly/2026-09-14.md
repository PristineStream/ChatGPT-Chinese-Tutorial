## 本周重点解读

### 1. Agent 后训练正在从“离线造数据”走向 Harness-native 数据闭环

NeoHorse-1 最值得关注的不是“recursive self-improvement”这个名字，而是它把真实 Harness 中的 **能力需求 → 模型路由 → tool trajectory → 结果质量** 直接变成后训练信号。相比传统先离线构造一批 SFT 数据再训练，这类方法更接近生产系统真正可持续的循环：

`线上任务 → 能力诊断 → 轨迹筛选 → Curriculum SFT / On-policy Distillation → Eval → 下一轮数据配比`

对于 SearchAgent，这意味着 Search query、tool call、observation、最终答案、Judge、成本和失败类型都应该被视为训练数据资产，而不仅是日志。

### 2. Agentic Search 的下一步是“复用搜索经验”，而不是每次从零 ReAct

VikingRAG 把成功的多轮 retrieval trace 保存为 experience edges，相似问题先复用经验，只有证据不足时才升级到完整多轮检索。这个思路和传统 Cache 不同：缓存的是**检索路径与结构化探索经验**，而不只是最终答案。

一个值得关注的系统形态是：

`Query → Experience Retrieval → Evidence Check → One-shot Retrieval / Multi-step Agentic Retrieval → Write-back Experience`

这会把 Agentic Search 从纯推理系统逐渐变成“会积累检索经验的搜索系统”。

### 3. Agent Memory 的关键从“记住什么”变成“写进去之前是否验证过”

Grounding Agent Memory 给 Memory Curator 增加只读环境工具，让它在持久化前检查代码库、数据库或业务环境的当前事实。结合近期 Memory Portability 研究，可以得到一个更稳妥的生产设计：

- Memory 必须保留 provenance / source；
- 可变化事实需要 `valid_from / valid_until / last_verified_at`；
- 写长期记忆前允许只读环境验证；
- 模型或 Embedding 升级时要做迁移评测，不能默认旧 Memory 自动兼容；
- 原始 evidence 尽量保留，避免只剩模型生成的压缩 notes。

### 4. RAG 排序目标正在从“语义相关”扩展到时间、成本和可复用性

TimelyRAG 说明相似度高不等于“当前有效”；VikingRAG 说明检索准确率高也不等于“值得付出多轮 Agent 成本”。生产 RAG / AI Search 更合理的目标开始变成多目标优化：

`Relevance + Freshness/Validity + Evidence Sufficiency + Token Cost + Latency`

尤其是政策、商品、价格、库存、供应商状态等会变化的数据，时间有效性应进入 Retriever / Reranker 特征，而不是最后让 LLM 自己猜。

### 5. Agent Eval 需要把“环境不可作弊”作为 Benchmark 的一部分

SWE-Bench Pro Verified 再次说明，Agent 比普通 QA 更容易出现 benchmark leakage，因为它能读文件、执行命令、访问网络、查看 git history。以后 Agent Eval 至少应拆成：

- Task correctness；
- Tool / argument correctness；
- Trajectory legality；
- Environment isolation；
- Hidden-information leakage；
- Cost / latency；
- 多次运行稳定性。

单一最终正确率很容易把“真正会做”和“碰巧找到了答案”混在一起。

### 6. 多模态后训练开始出现“专家化 → On-policy 汇总”的清晰路线

SenseNova-U1.5 分别训练审美、OCR / 双语文字、信息图、编辑等专家，然后通过 multi-expert on-policy distillation 收回统一模型。这个范式对文本 Agent 也有启发：可以分别构建 Search Expert、Tool-use Expert、Planning Expert、Memory Expert，再通过 on-policy trajectory distillation 合并，而不必一开始就让一个模型在所有任务上同时优化。

- **RAG Serving**：REVA（arXiv:2609.11209）开始利用历史 query-document-model attention trace 构建可复用 evidence view，把“历史生成行为”反过来用于下一次上下文压缩；报告压缩开销降低 5.3–15.6 倍，额外延迟低于 40ms。
- **Memory Portability**：`Does Your Agent's Memory Survive a Model Upgrade?`（arXiv:2609.05339）显示固定 Schema KG 在模型切换时最稳定，而模型生成 NOTES 的准确率可能随迁移方向波动约 -13.28pp 到 +9.91pp；50/50 混合新旧 embedding index 也无法获得完整迁移收益。

## 建议优先实践的四个实验

1. **Routing Log → Post-training Curriculum**：把生产 SearchAgent 的 query difficulty、路由模型、tool trajectory、Judge 分数、token/latency 统一存下来，按能力缺口构建 SFT + on-policy distillation curriculum；对比随机采样与 capability-guided sampling。
2. **Retrieval Trace Reuse**：把成功的多轮 Search trajectory 抽象成 `query pattern → retrieval steps → evidence type`，对相似 query 先复用路径；评估 task success、平均 search round、token 和 RT。
3. **Environment-Probing Memory Curator**：Memory 写入前允许 Curator 调用只读 Search / DB / Repo 工具验证事实，并与纯 trajectory-summary Memory 对比 stale memory rate、冲突率和最终任务成功率。
4. **Anti-Hacking Agent Eval**：对现有 Agent benchmark 增加 network off、隐藏 gold、清理 git history、工具最小权限和 trajectory audit，比较“原始得分”和“隔离后真实得分”的差距。
