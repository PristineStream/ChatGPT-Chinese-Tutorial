## 本周最值得深入的五个方向

### 1. Agent RL：从「最终答案对不对」转向「终态可执行验证」

ThinkingBox-Training 不需要让 LLM Judge 凭主观印象评估完成程度，而是令每条 rollout 运行于隔离的状态环境，再根据最终数据库是否满足任务条件计算 reward。它用训练集以外的 ThinkingBox-Bench 做 507×20 次复测，Qwen3.8-27B 在 50 个 GRPO steps 后：
- **pass@1**：51.70% → 60.78%（+9.08pt）。
- **observed 20/20**：38 → 107 个任务。
- **pass@20（至少一次成功）**：453 → 446 个任务（反而下降）。

第三点非常重要：追求可靠性可能损失“偶尔能做对”的覆盖面。建议 Agent 后训练同时输出 pass@1、pass@k、observed k/k、cost per dependable task，明确效益与覆盖的 trade-off。

原文：https://huggingface.co/blog/microsoft/thinkingbox-training

### 2. 多模态搜索：Embed + Rerank + Parse 需要端到端优化

NVIDIA 这一轮最有意义的不是单个榜单，而是把图像/文本联合检索、重排、OCR/文档解析当作一个整体。8B Embed 在 ViDoRe v3.1 得到 61.17 nDCG@10；1B BF16 得 58.38；Rerank 8B 的联合输入得到 60.49 nDCG@10。官方在固定 Agent 系统的对照中报告，加入重排可减少约 13%–14% 的每 query Agent 推理 token。

建议对国际化商品图搜、VQA 和文档 RAG 同时测：
- 多语言 + 图文混合的 Recall@K / nDCG@K；
- Parser 造成的文本/版面信息丢失；
- Rerank 后是否降低 Agent 再搜索次数；
- **E2E Good / Success、RT、总 token 和检索模型 GPU 成本**。

原文：https://huggingface.co/blog/nvidia/nemotron-retriever-world-class-agentic-retrieval

### 3. Agent Memory：「Trajectory → Playbook」与「SFT/RL 改权重」并行

IBM ALTK-Evolve 从历史 task attempts 中生成短指南，把正确执行顺序、身份验证、确认动作等规则加入 Prompt，在无需 SFT/RL 的前提下提升任务成功率和稳定性。需注意：完整版 guideline 在作者零售实验中把单次对话总成本从 $0.084 提高到 $0.139（+65%），因此只追成功率也可能偏离生产目标。

可与现有轨迹后训练并行做 A/B：
- No memory；
- top-k retrieved procedural skills；
- compressed high-support skills；
- trajectory SFT；
- skills + SFT。

核心指标：Success、Pass^k、Prompt tokens、Latency、Cost/Success。

原文：https://huggingface.co/blog/ibm-research/altk-evolve-bc

### 4. Agentic RL 的另一半是可信数据与环境

Snowflake Arctic-SWE 把「在 160 个可解任务上是否能长期稳定拟合」当作 RL 调参的首个 sanity check，而不是一开始就堆更大训练集。作者指出部分 SWE 训练任务的验证不足，会错误奖励无效修复。对 Agentic Search 的迁移非常直接：

1. 先建立可重放的检索状态环境。
2. 随机抽查 Reward 的 false-positive / false-negative。
3. 在小批固定任务上反复 overfit，并检查是否遗忘已会的技能。
4. 再引入 Hard Query、动态工具噪声和长轨迹任务。

原文：https://www.snowflake.com/en/blog/engineering/arctic-swe-agentic-rl/

### 5. MCP / Skills / RL Environment / Sandbox 开始分层标准化

Linux Foundation 10 月 22 日消息：AAIF 新增 Agent Skills（Anthropic）、Open Responses（OpenAI）、OpenEnv（Hugging Face）和 OpenSandbox（阿里巴巴）。对于 ToolHub 可将技术边界拆为：

- **MCP / A2A**：工具与 Agent 交互、发现和通信；
- **Agent Skills**：跨产品可复用的过程、指令、脚本与资源；
- **Open Responses**：跨供应商的模型请求/响应接口；
- **OpenEnv**：可复用、可验证的 RL task environment；
- **OpenSandbox**：安全执行环境和生命周期。

这是一组开源项目纳入治理的公告，不应误记成 MCP 发布了新稳定版本。

原文：https://www.linuxfoundation.org/press/agentic-ai-foundation-announces-four-new-projects-agent-skills-open-responses-openenv-and-opensandbox

## 下周可直接落地的四组实验

1. **Terminal-state GRPO**：搭建含任务状态与 Tool 执行的离线 SearchAgent 环境。Reward = 完成度 + 证据正确性 − 错误副作用；对比 Answer-Judge reward，统计 Pass^5 与 Cost/Success。
2. **Multimodal Retriever/Reranker 组合消融**：保持 Generator 与 Query Set 不变，对比 text-only、VL Embed、VL Embed+VL Rerank、加 Parser 的四个设置，分层统计中文/英文/跨语言/图表场景。
3. **Trajectory→Skill vs SFT**：从线上成功轨迹归纳工具使用 SOP，检索注入与纯 SFT 对照，并记录 token budget；避免只评成功率忽略成本。
4. **Small-set Overfit for Agent RL**：先固定一批可验证、可复现样本并检查 Reward 是否能稳定趋近满分，再扩展到噪声工具、多轮检索与不同语言。

## 本周趋势判断

- **可信可执行 reward 比再造一个 Judge prompt 更容易提供稳定学习信号，但环境搭建成本更高。**
- **搜索质量影响 Agent 的迭代次数和总成本，Embedding / Reranker 需要连同 Generator 做端到端评估。**
- **Agent 能力提升有两条路线：模型权重上的 SFT/RL，与推理环境侧的 Skill/Memory/Harness 优化。**
- **RL 环境、执行沙箱、Skills 与模型 API 的互操作标准正加速成熟。**
- **多模态系统正在从一次性理解走向持续状态建模与可执行动作。**
