## 本周重点解读

### 1. Agent 正从“每次重新推理”进入“经验复用”阶段

TRIAGE 的核心价值不只是省 token，而是把 Agent 历史执行轨迹从被动日志提升为可执行资产。一个值得长期跟踪的架构是：

`Trajectory → Pattern Mining → Skill Extraction → Semantic Routing → Deterministic Execution / ReAct Fallback`

这与传统 Memory 的区别很大：Memory 解决“记住什么”，Skill 解决“以后遇到类似问题直接怎么做”。对于高频工具任务，这可能比继续压缩 ReAct prompt 更有收益。

### 2. MCP 评测需要从 Tool Name Accuracy 升级到 Argument / Trajectory Correctness

Agent Seer 的结论很实用：在复杂工具 Schema 下，最容易失败的往往不是“选错工具名”，而是参数值不正确。生产评测建议至少拆成：

- Tool selection accuracy；
- Argument key accuracy；
- Argument value accuracy；
- 调用顺序和依赖关系；
- 工具失败后的恢复能力；
- 最终任务状态是否真实完成。

这比只用 function-call exact match 更接近真实 Agent 质量。

### 3. GRPO 的下一阶段问题是稳定性，而不只是 Reward 上涨

GCPO 提醒我们，on-policy RL 即使训练 reward 持续提升，也可能出现通用能力下降、回复变长、策略熵异常等问题。后训练实验中建议把以下指标加入训练监控：

- 主任务 reward / success rate；
- held-out 通用能力；
- response length；
- policy entropy；
- KL / update norm；
- 不同任务上的 capability regression。

也就是说，GRPO / DAPO 类方法不能只看最终 benchmark 分数，需要监控训练过程中“能力是否被挤出”。

### 4. 多模态 Agent 的关键不只是视觉能力，而是 modality routing

“Screenshots or Tools?” 最值得关注的不是 GUI benchmark 分数本身，而是同一工具对不同模型产生相反效果。这说明未来多模态 Agent 需要显式学习：

- 什么时候看截图；
- 什么时候调用结构化工具；
- 工具返回后是否还需要新的视觉 observation；
- 如何压缩已经被工具结果替代的视觉上下文。

这其实是一个多模态 routing / policy learning 问题。

### 5. MCP 安全正在从协议安全扩展到工具供应链安全

SandScope 把 MCP Server 当作第三方依赖来审计是一个重要信号。一个工具即使 Schema 看起来安全，其运行时仍可能访问文件、环境变量、网络并把敏感内容带回模型上下文。因此企业级 ToolHub 建议增加：

- 工具静态权限声明；
- 沙箱运行；
- 文件/网络/环境变量访问审计；
- 高风险 sink 检测；
- Tool output 的 prompt-injection / sensitive-data 扫描；
- 运行时 provenance。

## 建议优先实践的三个实验

1. **Trajectory-as-a-Skill 实验**：从已有 Agent 日志中聚类高频轨迹，抽取参数化 Skill，对比 Full ReAct、Trajectory Retrieval、Deterministic Skill 三种模式的成功率、Token、RT 和错误恢复能力。
2. **Tool Argument Judge 实验**：把现有 Tool Calling Eval 从“tool name 是否正确”拆成 tool / key / value / sequence / final-state 五层 Judge，验证哪一层最能解释端到端失败。
3. **GUI vs Tool Routing RL 实验**：在同一任务上同时开放截图动作和结构化 MCP 工具，用 GRPO 或类似方法训练“何时看、何时调工具”，并加入输入 token 成本作为 reward penalty。

## 本周趋势判断

- **MCP 竞争重点正在从“接入多少工具”转向 Tool Routing、Eval、Identity 与 Supply-chain Security。**
- **LLM 后训练开始更系统地解决 RL 稳定性、能力保持和长度膨胀，而不只是追求单任务 reward。**
