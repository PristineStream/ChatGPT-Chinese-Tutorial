## 本周重点解读

### 1. Tool Use 后训练开始从“是否调用对工具”进入“如何探索工具空间”

ToolCompass 最值得关注的不是又一个 GRPO 变体，而是它把 tool trialing 单独建模。真实 Agent 在未知工具集里需要探索，但现有 outcome reward 往往只能告诉你最终成败，无法区分“必要探索”和“无效乱试”。

对 SearchAgent / ToolHub，可以把 reward 拆成：
- 最终任务成功；
- 工具是否必要；
- 试错次数与预算；
- 未见工具的功能迁移；
- 参数值是否正确，而不仅是 tool name 是否正确。

### 2. Search 基础设施也开始 Agent 化

SELF-INDEX 把“索引怎么建”从离线人工工程改成持续优化过程：从线上失败 query 中诊断原因，改写 index keys，再验证是否真的提升后才落库。

这比单纯重训 Embedding/Reranker 更接近真实搜索系统迭代方式。尤其适合：
- 长尾 query；
- 新领域冷启动；
- Agent Memory 检索；
- Query 分布持续漂移的国际化搜索。

### 3. Agent Eval 需要增加“重复运行稳定性”

平均成功率会掩盖同一个任务忽好忽坏的问题。实际生产更关心“这个任务是不是每次都能成功”。

建议在传统 pass rate 外增加：
- Pass^k / Consistency@k；
- trajectory variance；
- tool sequence variance；
- final answer variance；
- failure mode entropy。

这对 Judge 也有启示：一次 Judge 结果不能完全代表一个 Agent policy 的稳定性。

### 4. Memory 正从“事实存储”转向“程序性经验”

Designer-RSI 的价值在于把用户真实流量中的成功/失败轨迹沉淀成可复用 Skill，而不是保存整段聊天历史。这个方向和“Trajectory as Skill”高度一致：

**生产轨迹 → 聚类/抽象 → Skill / SOP → 下次直接复用 → 执行反馈继续修正。**

对长期 Agent 来说，这种程序性记忆往往比单纯事实记忆更能提高成功率和降低 token 成本。

### 5. Agent RL 的核心资产正在变成环境

从当前公开实践看，Agentic RL 的四个核心组件越来越稳定：
1. Task；
2. Harness；
3. Sandbox；
4. Verifier / Reward。

真正难复制的是环境和可验证任务，而不是 GRPO/PPO 本身。对训练 SearchAgent，应优先建设可恢复、可重复、可并发的搜索环境，而不是只继续调 RL loss。

## 建议优先实践的四个实验

1. **Tool Trialing Reward**：在现有 SearchAgent GRPO 中增加 unnecessary-tool-call penalty 和 exploration budget，观察 E2E 成功率、平均 tool call 数和 unseen tool 泛化。
2. **Self-Evolving Index**：基于 Judge badcase 自动定位 retrieval miss，对 query rewrite / index key rewrite / metadata enrichment 做自动 propose→validate→apply 闭环。
3. **Agent Consistency Eval**：每个评测样本重复 rollout 5 次，同时统计 Mean@5、Pass^5 和 trajectory variance。
4. **Trajectory → Skill Memory**：把历史成功轨迹压缩为工具级 SOP/Skill，在推理时按 query 检索注入，并测 token、RT、成功率三项收益。

## 本周趋势判断

- **Agent 后训练正在从“训练模型”扩展为“训练模型 + 工具探索策略 + 环境系统”。**
- **RAG / Search 的优化对象开始从 Retriever/Reranker 延伸到 Index 本身。**
- **Agent Memory 正逐步从保存事实转向沉淀程序性经验。**
- **Agent Eval 的重点正在从平均成功率转向稳定性、可重复性与动作安全。**
- **多模态 Agent 的下一阶段瓶颈将更多落在推理延迟和系统工程，而非单纯 VLM benchmark。**
