## 本周最值得学习的三条主线

### 1. 从“检索模型”升级到“检索策略”

传统 RAG 主要优化 Embedding、Reranker 和 Top-K；GRASP 代表的新方向是让 Agent 学习何时搜索、调用哪类检索工具，以及返回多细的上下文。真正的优化目标应从单点 Recall/NDCG 扩展到任务成功率、搜索轮数、Token 成本和错误恢复能力。

### 2. Agent 基础设施必须把安全与评测前置

Agent 能调用工具、访问网络和修改状态后，失败不再只是“回答错”，还可能变成越权访问或真实动作风险。应把沙箱、最小权限、网络隔离、完整轨迹、结果验证和多次 trial 纳入默认 Harness，而不是上线后补救。

### 3. 多模态 RAG 的关键正在转向统一排序和工程效率

统一文本与页面图像的 Reranker，可以减少双模型路由、分数对齐和部署复杂度；但 Listwise 的收益依赖 cross-document attention，也会显著增加视觉编码和解码成本。更实际的优化顺序通常是：先提升一级召回，再缩小 Rerank 候选集，最后再考虑缩模型。

## 建议本周落地的实验

1. **Agentic Retrieval 对比实验**：固定 RAG、Query Rewrite、多工具检索策略三组对比，同时记录任务成功率、平均搜索轮数、Token 和 P95 延迟。
2. **统一多模态 Reranker 实验**：文本 Cross-Encoder、视觉 Pointwise、混合 Listwise 三种方案，在同一候选集上比较 NDCG、Good Rate 与单 Query 成本。
3. **Agent 安全回归集**：构造工具越权、提示注入、恶意网页、凭证访问、错误文件修改和超时重试等 case，并要求结果验证器检查真实环境状态。
4. **MCP 兼容性检查**：针对现有 MCP Server 验证无状态化、OAuth/OIDC、JSON Schema 2020-12、Tasks 和弃用能力的迁移影响。

## 趋势判断

> Agent 系统的竞争重点正在从“模型是否会调用工具”，转向“是否能以可控成本选择正确工具、检索合适粒度的上下文，并在真实环境中安全、可验证地完成任务”。
