## 核心解读：本周学什么

### 1. 多轮 RL 的收益需要和执行预算一起报告

BudgetMix RL 研究的核心提醒：长轨迹 RL 的提升不能只报告“无限轮可重试”的 Pass@1。相同模型在不同最大轮数 T、并行尝试次数 K、最大工具调用数和 Token 预算下，可能有不同表现。研究指出改善尤其集中于 error recovery，而非每一步的原始决策质量。建议完整报告 Pass@(K,T)、recovery success、tool calls、token、RT，并在固定预算下做对比。

### 2. Progress Advantage 与 ForeCritic 给 Judge / Reward 两条不同路线

- Progress Advantage：由训练后策略与参考策略的 log-prob ratio 导出过程分数，关注 step 级进展、失败定位与不额外训练独立 PRM 的可能性；11 月 2 日更新的是旧论文版本，不能写成 11 月首次发布。
- ForeCritic：不预测候选程序执行时发生什么，只判断哪一个更可能获得更好实际结果，以低成本 pairwise decision 减少昂贵真实执行；10 月 28 日首发，这周属于补充学习。
- 两者都不能替代环境级 ground truth：要额外检查 reward hacking、校准、不同任务域泛化以及偏好/标注数据质量。

### 3. RAG 的真实收益应按系统组合测量

LASAGNA 表明检索、重排、Query Rewrite、Context Compression 等局部优化常存在交互效应，不能把单模块离线 gain 简单相加。建议以同一数据和 budget 做 full factorial / 消融对照，分别汇报 nDCG、证据覆盖、Answer faithfulness、E2E success、平均 Token 和 p95 RT。

### 4. 多模态 Agent：证据理解、执行动作与安全防护要贯通

Multimodal-SEA 的任务使用伪造文档、图片和复杂情境，同时基于工具日志验证后果；它揭示安全指令本身并不能保证识别伪造多模态证据。TAP-RAG 则展示如何按任务决定需要文本、页面图像还是结构信息，并在证据不足时拒答。国际化多模态场景建议建立中英文对照数据、图文矛盾集和工具执行后验指标。

### 5. MCP 规范与 Harness：本期没有证实新的正式 MCP 协议版本

当前可核实的官方规范是 [MCP 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/)：stateless core、header routing、Multi Round-Trip Requests、可缓存工具列表和扩展框架。不要把社区提案或实现讨论说成最新稳定版。10 月 30 日 OpenAI Agents API 更新了 session 动态工具列表与后台压缩，对 ToolHub 工程更具近期参考价值。

## 建议动手验证的四个实验（适合 Agentic Search / Judge / RL）

1. **Budget-Sweep Agent RL**：固定 Agent 和工具环境，网格搜索 max turns = {2,4,8,16}、parallel samples K = {1,3,5}，比较 GRPO vs BudgetMix-style 混合预算训练，统计 Pass@(K,T)、error recovery、cost per success。
2. **Implicit PRM vs Pairwise Reward**：以历史 Trajectory 构建 step 级 progress advantage 和候选答案 pairwise selector，比较人工一致率、calibration (ECE)、GSB 与在线失误恢复率；需避免训练-评测任务泄漏。
3. **Composable RAG**：选 2 种 Embedding × 2 种 Reranker × 2 种 Query Rewrite × 2 种 Context Compression，控制预算比较完整链路 Answer Faithfulness、引用支持度及成本，避免只看离线 Recall。
4. **Multimodal Tool/Safety Eval**：在 VQA / 看后问构建图文互相矛盾、截图伪造、无关图像注入和 OCR 易错样本；同时量化任务符合率、误拒率、不安全动作率、工具日志最终状态。

## 同日增量解读（2026-11-09）

以下内容是对原有九项资料的补充，不替代前文。新增六项的来源与日期已在首页表格逐项标注。

### 1. RubriX：分清评分架构、训练分布与缓存收益

[RubriX 论文](https://arxiv.org/abs/2610.34875)采用非生成式评分：待评输入包含对话、回答和 criterion，各等级描述单独编码，再用缩放余弦相似度的 softmax 输出概率。建议将其作为 Jev 风格判决研究的架构对照，而不是直接据一个 held-out 数据集宣称全面优劣。

作者报告在训练领域内未见 Rubric 上的 exact accuracy 为 75.4%，对照 Jev 为 57.1%；但在人类标注基准上结果更混合，Jev 在多项排序相关性指标上仍占优。约 28ms 的延迟依赖等级向量已经缓存，API 对照还扣除了估计网络时间。公平评测应区分本地服务延迟、端到端延迟、缓存预热以及新 Rubric 编码成本。

[作者官方介绍](https://cobuildx.ai/blog/rubrix-rubric-judge)发布于 2026-10-16，arXiv 首稿为 2026-10-26；其他平台 11-04 的收录日期不能当作首次发布日期。[模型与适配器](https://huggingface.co/CobuildX-AI/RubriX-8B)可用于复现实验。

### 2. 多语言 Rubric：一致不等于正确

[Same Rule, Different Verdicts](https://arxiv.org/abs/2611.04091)在七个模型、60 段翻译对话和 144 个构造边界案例上比较判决，共 51,744 次请求。跨厂商模型在韩语 Rubric 下的 Cohen's kappa 为 0.687，英语为 0.745；同一模型面对语义等价句式时有 11%–15% 的判决翻转。

这些结果支持把语言和句式纳入鲁棒性测试，却不能证明英语 Rubric 更符合人工偏好：该研究没有人工标注，而且材料由模型起草。迁移到中文或其他语言时，应先由人工确认不同版本语义等价，再分别比较对人工真值的正确性和改写稳定性。

### 3. PromptOps：用独立时间切片防止越调越偏

[PromptOps](https://arxiv.org/abs/2611.07123)将持续维护拆成四个决策，并比较 GEPA、SIMBA、Rubric Synthesis 和两种 exemplar selection。作者观察到，在受控评分分布变化后，持续校准可恢复表现，但更新时机和算法选择依赖具体场景。

建议把近期反馈作为校准集，保留独立未来时间段的人工集与固定锚点集。Prompt 更新后同时观察逐维准确率、分数分布、重大误判和历史能力退化，不以“模型更常输出高分”作为改进证据。

### 4. RAG 与多模态重排：分别验证迁移性、离线成本与热缓存收益

[CacheGraft](https://arxiv.org/abs/2611.07393)、[ArcRAG](https://arxiv.org/abs/2611.06481)与[miniReranker](https://aclanthology.org/2026.findings-emnlp.1849/)分别改变证据表示、图接口归纳、视觉计算复用。三者解决的问题不同，不能据单一性能数字给出统一排名。建议分别计入模型适配与缓存存储成本、图构建差异、冷/热缓存命中率，再以同一任务预算比较检索质量、引用支持度、答案质量和 p95 延迟。

### 增补实验设计

以下为建议设计，不是论文已经验证的业务结论。

| 实验 | 最小对照 | 主要指标 |
| ---- | ---- | ---- |
| 非生成式 Judge | Jev / 生成式 Judge / RubriX；相同业务人工集，按 Rubric 与时间留出 | exact accuracy、加权 kappa、排序相关性、置信度校准、严重误判、冷/热缓存 p50/p95 |
| Rubric 改写鲁棒性 | 固定样本，人工确认等价的中英文、肯定/否定/条件/例外版本 | 对人工真值准确率、语义等价判决翻转率、逐语言差异 |
| Judge 持续校准 | 固定 Prompt、固定频率更新、漂移触发更新 | 独立时间切片准确率、锚点集回归、误差分布、标注与推理成本 |
| 多模态重排缓存消融 | 原始格式、vision-first、缓存、稀疏化逐项加入 | nDCG、证据覆盖、答案正确率、冷/热缓存 RT、缓存容量与失效成本 |

**增补阅读顺序建议：RubriX → Same Rule, Different Verdicts → PromptOps。** 三篇依次回答评分架构是否高效、评分规则是否稳定，以及上线后如何持续保持可信；其余三篇作为搜索系统的技术储备。
