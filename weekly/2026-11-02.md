## 重点精读与技术启示

### 1. ACARe：检索相关性应该面向 Agent 当前任务，而不是孤立 Sub-query

传统 Reranker 仅输入 `(sub_query, document)`；但 Agent 可能已经完成部分检索，当前 sub-query 只是局部步骤。ACARe 引入原始问题、可见 Agent 上下文和 sub-query，并通过 context dropout 兼容没有推理轨迹的黑盒模型。

**可复现实验**：固定 Retriever Top-K，用同一训练数据依次比较 `sub_query`、`original_query+sub_query`、`original_query+sub_query+plan/context`；跟踪 nDCG@10、Answer GSB、平均 Search Calls、Token/RT。必须验证“局部相关”与“最终答案有用”是否一致。

### 2. MPO：长轨迹 RL 的信用分配单位可以是 Turn

Agent 每个决策 Turn 决定后续工具调用和状态转移，但常规 Token RL 把整个序列放在单一粒度处理。MPO 结合 Multiscale Advantage Estimation 和 Turn-level Importance Sampling，提示 Agent RL 应把关键 turn 的 policy change 与 token 内部概率更新区分开。

**可复现实验**：在相同 SearchAgent rollout、reward、batch、算力预算下比较 GRPO、按 Turn 重加权、MPO 风格分层 advantage。观察 E2E success、rollout 长度、KL、tool-call pattern 和训练稳定性，避免只比较 reward 曲线。

### 3. SkillMem：程序性记忆的载体不只有文本和模型权重

SkillMem 使用成功/失败轨迹提取文本程序，然后通过 behavioral distillation 将 Skill 的 token-level 作用编译为外部 latent memory。训练时冻结 backbone，只训练记忆和共享读取器；推理时不同角色按当前状态读取同一个 Skill。

**可复现实验**：对同一 Skill Library 比较文本注入、KV Cache、LoRA、Latent Memory，在小模型与多 Agent 场景下测成功率、Skill 选择准确率、prefill/token 成本、总延迟、技能库扩张后的内存占用。论文的最高加速来自特定基线和系统，不能直接外推业务。

### 4. GAD：把验收条件和验证节点放到长程任务执行图里

单纯增加 Planner/Worker/Critic 不能自动解决长程任务；信息在共享上下文中淹没，分开上下文又可能丢失全局目标。GAD 引入保留任务目标与验收条件的动态依赖图、子任务分裂、基于证据的信息传递以及早期验证和恢复。

**可复现实验**：在 Deep Research 中拆分 `plan → search → evidence → answer → verify`，让每个节点明确输入、验收条件、失败回退；比较 single-agent、固定 DAG、动态 DAG 的最终准确率、重复工具调用、Verifier 发现错误时间和成本。

### 5. MCP：评测从“调用正确”走向“效果正确 + 故障恢复”

DynamicMCPBench 使用 live MCP Server、path-agnostic effect checkpoints 和 pass³，而 MCP-Injector 进一步引入超时、错误返回、间歇性故障、持久性故障。MICA 则证明，即便执行能力相同，MCP 与 CLI 的表示也可能显著改变 Agent 的规划与恢复行为。

**可复现实验**：构建分层 Tool Agent Benchmark：
- Tool Selection / Argument Accuracy；
- Action Side Effects / Final State；
- Retry / Timeout / Malformed Result / Stale Observation；
- MCP vs CLI 的等语义对照；
- Pass@1、Pass³、State Correctness、Recovery Rate 与每次成功成本。

### 6. RAMP 与多模态 System-One Reranking：搜索系统开始优化接口与决策形态

RAMP 的思路是让 Query Policy 识别 Retriever 后端差异，而不是强迫所有 Retriever 适配同一种 query。另一方面，多模态 Reranking 的 System-One 设计使用 VLM 对候选标签概率的单次前向推断，避免为每条候选生成解释。

**可复现实验**：选择 BM25、dense、hybrid、web API 四个后端做 query generation 自适应；视觉 Rerank 对比 pointwise Yes/No、listwise selection probability 与专用 VL-Reranker。注意控制候选数量、模型规模与 RT，不把模型变大带来的提升误判为方法提升。

## 面向 Agentic Search 的四项优先实验

1. **Context-Aware Rerank**：构造原始需求 / sub-query / plan / evidence-gap 四种上下文组合，离线 nDCG 与 E2E Answer GSB 联合评估。
2. **Turn-Level RL Credit**：给 SearchAgent 的工具调用 Turn 与最终答案生成 Turn 分别估计贡献，比较 GRPO 和分层 Advantage。
3. **MCP Fault + State Eval**：在现有工具评测上增加故障注入、真实副作用检查、重复运行 Pass³。
4. **Trajectory → Skill Distillation**：比较原样轨迹检索、文本 Skill、KV Skill、Latent Skill 的成功率与效率，构建按 Skill 类型自适应选择方案。

## 本周判断（研究视角）

1. **Agentic Search 的重排目标从单步 query relevance 转向面向全任务的 evidence utility。**
2. **Agent RL 的关键问题进一步下沉到 Turn-level credit assignment 与长期策略稳定性。**
3. **Tool/MCP Eval 需要同时测业务终态、重复可靠性、故障下恢复，而非只看 Tool 命中率。**
4. **Skill Memory 可能形成文本、KV、LoRA、Latent 等可选择的不同表示，选型需看规模和总成本。**
5. **多模态 Rerank 正在尝试从逐条生成式打分转向低解码成本的候选决策。**
